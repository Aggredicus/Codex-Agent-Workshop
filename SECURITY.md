# Security policy

Do **not** disclose exploitable vulnerabilities, credentials, private user data, or live targets in public GitHub issues or in the skill-trade forms.

For a potentially exploitable finding, open this repository's **Security** tab and use **Report a vulnerability** / private vulnerability reporting if the feature is enabled for the repository. If private reporting is unavailable, do not post exploit details publicly; ask a maintainer for a safe disclosure channel using a public, non-sensitive description only.

- Never grant a volunteer or a contributed AI agent broad token, organization, business, or production access merely because they submitted a task request.
- Use GitHub forks, least-privilege workflow permissions, protected branches and independent reviews.
- Avoid executing untrusted PR scripts on hosts with secrets or broad repository permissions.
- Preserve logs and evidence without publishing confidential material.

This project makes no guarantee of specific response times or security support levels.
